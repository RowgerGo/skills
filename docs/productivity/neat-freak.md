## What it does

`neat-freak` 在开发或交接收尾时，把项目文档、规则文件和 [agent](https://www.aihero.dev/ai-coding-dictionary/agent) 记忆对齐到核实过的现状，也会检查项目里的规则是否落地。它以当前代码、配置和运行证据为准，就地修正过期说法，让同一条现行结论只有一个权威出处。

## When to reach for it

可以调用 `/neat-freak`，也可以在对话里输入 `/neat` 或说「跑一下洁癖」。开发结束后明确要求同步文档和记忆、纠正规则或记忆冲突、做交接前的知识收尾，或检查项目规则是否执行时，agent 可以自动选用。

如果只想改代码、格式化 JSON 或润色周报，直接说明要改的内容。

## Prerequisites

需要能读取项目文件。修改限于你授权的范围，默认以当前项目为单位。Git 有助于核对改动和判断临时文件能否清理，小项目也可以在没有 Git 的情况下做知识收尾。

## 一个权威出处

比如启动命令变了，把完整的上手步骤写在 README，规则文件只保留执行约定和指向这段说明的链接，记忆保留以后还用得上的教训。接手的人和下一个会话都能找到同一条可照做的命令。

## Common questions

**整理文档和记忆时，会顺手删掉临时文件吗？**

这个请求下，agent 会把临时文件里仍有用的内容并入正式文档，再列出删除候选和理由。明确授权清理后，它先核对改动已合并并上线、没有未提交的工作，也没有只留在候选文件里的内容，再在授权范围内清理。

**Codex 自动生成的记忆过期了，可以直接改吗？**

这种记忆按只读处理。agent 会报告发现的过期条目，找到平台公开的入口才会通过它处理。当前平台允许自行维护的项目记忆，可以按本次请求的范围整理。

## It's working if

- 按 README 的命令能启动项目，使用到的路径和配置都能在项目里找到。
- 每条现行结论都有一个完整出处，过期内容已就地修正，历史记录仍可查。
- 汇报写清了实际改动、规则审计中发现的问题，以及仍待确认或未核实的事项。

## Where it fits

`neat-freak` 是开发结束或交接前可使用的独立维护技能。遇到一次执行过程特别费力，想根据过程记录找出下次可改善的规则或工具时，可以用 [retro](https://aihero.dev/skills-retro)。需要在整套技能里找入口时，使用 [ask-matt](https://aihero.dev/skills-ask-matt)。
